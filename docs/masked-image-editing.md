# 蒙版局部修改

## 后台配置

模型管理 → 编辑图片模型 → 生成能力 → **支持蒙版（局部重绘）**。

- 存储字段：`market_model.config.supportsMask`，默认 false。
- 开启表示管理员已确认该模型及其上游线路支持透明 PNG 蒙版。
- 主模型从已上架、非维护、支持蒙版的图片模型中按 `sort_order ASC, use_count DESC, id ASC` 选择，与公开模型目录完全一致；建议为候选模型设置不同的排序值以固定优先级。
- 多个模型开启时，调整后台顺序即可调整主模型；没有候选时明确提示，绝不回退普通编辑模型。
- 生成前后端均使用同一模型 ID、画质及清晰度计价。弹窗期间主模型变化会拒绝旧提交，不静默改价。
- 弹窗同时提交 `expectedPointCost`；同一模型的后台价格变化时也会在扣费前拒绝旧报价，提示重新确认。已接受请求仍按既有幂等记录恢复。
- 明确不支持 `image_to_image` 的候选会被排除，前后端使用相同规则。
- Relay 模型同步保留管理员配置；不改变图片生成的全局主模型或 AI 聊天配置。

## 使用

无限画布图片、角色、场景节点的「局部修改」，以及工具中心「局部重绘」，共用蒙版编辑弹窗。
用画笔涂抹选区（包括新增物体和必要阴影的空间），可擦除、撤销、清空；输入修改描述后生成独立结果。
画布保留原节点并连接结果节点。蒙版编辑期间自动版本更新暂停，避免丢失笔画。
原图加载 30 秒超时，关闭弹窗会取消下载/解码并释放 Blob URL；工具中心提交失败会显示具体原因并保留选区。

## 请求与结果

- 沿用 `image_to_image`，新增任务 input 的 `maskImage` URL。
- 只允许一张原图、一张蒙版和单张输出。原图/蒙版从本站存储读取，提交扣费前验证尺寸、格式和选区。
- 原图和最终结果最多 64 MiB，蒙版最多 32 MiB（与 APIRouter 安全下载上限一致），解码最多 2000 万像素；重绘图像处理串行限流，避免并发解码耗尽内存。
- 原图格式支持 PNG、JPEG、WebP；GIF/AVIF 等浏览器可显示但服务端无法保持一致坐标的格式会在编辑器中提前拒绝。
- FlowLight 将 `maskImage` 转为 APIRouter `/v1/images/edits` 的 `mask` 参数。
- 蒙版为透明 PNG：完全透明表示修改，不透明表示保留，部分透明用于边界混合。
- 上游图片归档后，服务端将选区内容合回原图，最终保存无损 PNG。原图不会整体缩放或二次 JPEG 压缩。
- 同比例的不同分辨率结果只缩放生成图层；明显不同画幅直接失败，不强行拉伸原图。
- 兼容上游短边对齐到 16 像素的舍入（最大 15.5 像素且不超过输出长边的 1.5%），不把正常 3:2 尺寸误判为改变画幅；原图仍不缩放。
- 8 位和 16 位 PNG 原图分别使用对应精度合成，未选区域不会被整体量化到 8 位。
- JPEG、PNG、WebP 的 EXIF 方向使用统一坐标：后台按旋转/镜像后的画面检查蒙版和合成。需要转正的原图在调用上游前另存为无损 PNG，避免不同供应商对 EXIF 的处理差异；历史来源仍保留原链接。
- 原图方向由服务端计算并保存到任务，不接受客户端伪造方向提示。已有任务恢复同样使用转正后的坐标。
- OSS 读写传入请求 Context，超时和取消能结束实际存储请求。
- 读取原图和蒙版前复用文件下载权限校验；同属本站桶不代表当前用户有权读取。
- 生成中断恢复同样执行合成；合成失败按现有任务失败/退款流程收尾，不发布整图重绘结果。

## APIRouter 部署要求

需要同时发布 FlowLight 前后端和本轮 APIRouter 的蒙版协议修改。
APIRouter 的 `V1ImageController.EditRequest` 接收 `mask`（兼容 `mask_url`），保存到任务 extras；路由只选择明确实现蒙版传递的适配器。

当前已接通 **CCGO 非 Banana 图片编辑线路** 的 multipart `mask` 参数。Banana 及其他尚未实现蒙版的适配器会被排除，不能只在 FlowLight 勾选开关就让不支持的上游具备该能力。
蒙版读取失败会停止调用，不再降级为无蒙版编辑。公开蒙版 URL 需使用 HTTPS（443）；下载复用受限抓取器，并有体积、超时和临时文件清理。

验证使用本地存储、模拟上游和像素对比；未使用真实供应商 Key 调用付费生成。上线前需用目标蒙版模型完成一次实际验收。
