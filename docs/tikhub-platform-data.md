# 平台专属分析数据（2026-09-05）

## 核对依据与接口选择

使用 TikHub 完整 [OpenAPI](https://api.tikhub.io/openapi.json) 核对接口目录、参数和说明，目录不受市场页面分页影响。六个平台的目录共 705 个路径：抖音 332、Bilibili 87、小红书 45、YouTube 34、TikTok 168、快手 39（含 Demo、商业数据、直播、电商等分类）。完整端点索引见 [CSV](tikhub-platform-endpoints.csv)。不是每个路径都适用于单个公开账号，也不应对一次查询无差别调用全部路径。

发现并修复的接口错误：

- 小红书 `/app_v2/get_mixed_note_detail` 不在当前目录。改为 `/get_image_note_detail` 获取两种笔记的资料；明确为视频时，按官方流程再取 `/get_video_note_detail`。
- YouTube `/web/get_channel_videos_v2` 不在当前目录。改为 `/web_v2/get_channel_videos`，参数使用 `channel_id / language_code / need_format`。
- TikTok 账号作品由精简 V3 列表改用完整 `/app/v3/fetch_user_post_videos`。
- Bilibili 详情补查的参数是 `bv_id`，返回字段才是 `bvid`。

其他相关说明：[小红书用户信息](https://docs.tikhub.io/420136395e0)、[TikTok 用户信息](https://docs.tikhub.io/186826106e0)、[Bilibili 专项核对](tikhub-bilibili-audit.md)、[抖音专项核对](tikhub-douyin-audit.md)。当前 OpenAPI 的通用 `ResponseModel.data` 没有完整的上游字段 schema；因此响应兼容使用已验证样例、文档字段和明确的对象路径，不将单元测试样例等同于生产查询结果。

## 取数与展示

| 平台 | 作品与账号专属信息（有值时显示） |
|---|---|
| Bilibili | 播放、点赞、投币、弹幕、评论、收藏、分享；视频分区、原创/转载、AV/BV 号、分 P 目录、分辨率；UP 主等级、认证、投稿/专栏累计播放或阅读 |
| 小红书 | 点赞、收藏、评论、分享；图文与视频笔记、图片列表、笔记话题、地点、更新时间；小红书号、公开属地、认证及「获赞与收藏」合计 |
| YouTube | 观看、点赞、评论；频道/订阅者、语言、分类/关键词、章节与字幕轨道、可见范围、直播状态；频道累计观看、加入时间、地区和认证 |
| 抖音 / TikTok | 点赞、评论、分享、收藏、播放和下载（上游返回时）；音乐、音乐作者、原创音乐、话题、置顶、公开地区/地点/语言；用户名、认证和公开账号信息 |
| 快手 | 观看、点赞、评论等返回的互动；配乐、话题、地点和置顶；快手号、认证与公开地区 |

展示原则：

- 保留原有暗色科技主题和右侧报告，表格按平台和本次实际数据动态生成列。详情、账号样本、图表和 AI 提示词共用数据定义。
- 图表可切换播放、收藏、投币等实际有值的指标；无播放量时也可使用其他指标。增加内容形式、话题/分区分布与平台资料档案。
- 互动次数包含 B 站投币、弹幕；下载次数单独展示，不加入互动率。互动率仅使用同时存在分子和正播放量的样本，次数不是独立人数。
- 缺失不等于零。YouTube 不凭空列出收藏/分享指标；小红书合计获赞与收藏不改名为点赞；图文的背景音乐不当成视频。
- 只读取目标作品/作者的指定对象，不从推荐作品、音乐作者或评论用户借用统计。标题、发布时间、时长也采用目标对象的直接字段。
- 作品图集最多保存/展示 40 张，AI 输入仍限 9 张，避免一次归档大量图片造成资源峰值；分 P / 章节最多 100 条，标签最多 40 项。完整详情保存在快照中，AI 提示词使用有界摘要。
- 作者资料只从目标作品的作者对象或明确的账号接口取值；支持账号资料与统计分开包装，YouTube 展平的频道信息也不会混入视频播放量或文案。作品封面、分享地址不借用配乐或其他作者的信息。
- 小红书支持外层保存笔记 ID、内层 `note_card` 保存内容的结构；空 `statistics` 不会挡住有效的 `interact_info`。视频补查以笔记自身的视频地址为准，并校验补查结果的笔记 ID。
- 兼容空标题/空文案但有媒体信息的 TikTok、快手作品。快手将作者身份放在 `photo`、账号统计放在同级 `counts` 的结构单独投影，不把作品点赞数算成账号累计获赞。
- 发布日期统一识别秒/毫秒时间戳、ISO 日期时间及 `YYYYMMDD`。无效日期不参与图表或发布频率；只有日期的样本不推断小时。表格、时间轴与样本日期范围保留日期精度，避免跨时区提前一天。

## 补查、快照与限制

账号最多展示 12 条样本。B 站、小红书、YouTube 列表缺失关键互动字段时，按作品 ID 补查详情：最多 12 次、同时最多 3 次，共享 18 秒补查预算，整次分析最多 55 秒。部分失败或超时保留已有列表数据，并提示未补全的样本数；不会无限重试。短视频平台使用较完整的作品列表，避免无条件逐条加请求。

详情补查按字段合并，保留列表中已有的媒体地址、图集、投币/弹幕等专属统计、标签与目录；详情返回的真实 `0` 优先于旧值。AI 输入超预算时优先压缩附加资料和文案，保留样本统计；完整快照不受影响。长中文输入与多章节的回归样例已验证在 30 KiB 提示词预算内，低于技能接口 32 KiB 上限。

YouTube 的流地址只在目标响应的明确包装中查找；缺少 `formats` 时不去推荐视频中找替代地址。按 [TikHub 视频流 V2 文档](https://docs.tikhub.io/419083091e0)，使用音画合并的 `formats`，不将 `adaptive_formats` 的分离轨道当成完整视频；明确标记仍需解签的地址不使用。

新增数据直接进入原有 `SnapshotJSON`，不需要迁移数据库；用户和管理员记录都沿用现有所有权控制。回看历史不会重新请求 TikHub，也不会重新扣分析积分。老记录只能恢复原先保存的字段，需用户主动「获取最新数据」才能获得新增字段。

公开资料不包含所有创作者后台指标。目录中需要账号 Cookie、创作者权限或商业达人库的接口不自动调用；未授权的完播率、真实受众年龄/性别分布、转化和历史粉丝曲线不能用样本猜测替代。
