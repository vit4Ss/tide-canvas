## 在哪里使用

部署更新后的后端并启动，系统自动补齐50个视频草稿，不需要再上传ZIP。后台 → 创作模板 → 灵感做同款 → 视频 → 草稿/已下架；可按编号或名称搜索，例如「F01」「山水景区」「社区活动」。

原来的20套门店与食品厂模板保留。旧模板、新模板的运营修改、上架状态和删除状态都不会被启动导入覆盖。

上架步骤：

1. 核对配方、分类、素材用途，按需要补充运营已确认的事实。
2. 指定支持30秒、9:16和5个参考图片位置的模型；也可让「检查生成配置」寻找兼容模型。已有校验会检查实际参考图上限、提示词长度、输出规格和价格，不会自动把30秒缩成15秒。
3. 上传封面，或主动使用后台「AI生成封面」。本包没有成片，不能将封面当作已生成效果；视频预览可选。
4. 使用真实素材试做后上架。前台继续走上传、询价、确认积分和生成流程。

## 配方适配

原包面向文本智能体，包含客户填写表、生成另一段提示词的指令，以及30秒15镜的叙事骨架。平台没有客户文字填写步骤，因此没有原样把这些编写指令交给视频模型。

执行版保留每套的主题、推荐视听风格、15镜顺序和摄影说明、话术结构、行业禁错；明确直接生成30秒9:16视频。没有价格、期限、权益或服务证据时，按原包规则生成无价格概念宣传版，禁止补造促销或真实项目承诺。口播骨架中的待填变量改为条件指令，不直接显示或朗读。

额外提供一个选填资料图片位置，可上传清晰的套餐规则、票种或项目服务说明。没有新增用户文字表单，也没有后台自动调用文本模型的收费步骤；管理员仍可编辑完整私有提示词。模型识读资料和成片视觉效果仍需试做确认，导入检查不代表实际生成效果已验证。

## 素材位置

各分类的显示名称分别适配餐饮、景区、美业、企业、店铺和物业，语义位置一致：

| 位置 | 用途 | 要求 |
| --- | --- | --- |
| 1 | 人物、讲解人或管家照片 | 选填；缺失时使用虚构成年介绍者 |
| 2 | 门面、场景、企业入口或社区环境 | 必填；提供本次创作的场景依据 |
| 3 | 室内、操作空间、设施或公共空间 | 选填 |
| 4 | 菜品、作品、产品、项目或活动现场 | 选填 |
| 5 | 套餐规则、业务证明或已确认服务资料 | 选填；无法辨认的信息不采用 |

执行配方使用固定位置占位符。实际只上传位置2、4、5时，场景绑定实际第1张图，产品绑定第2张，资料绑定第3张；人物缺失不会被产品替代。沿用已有文件归属、可选位置、额度、扣分及失败退款逻辑。

## 内容与可复现导入

- 私有目录：internal/handler/studiotemplate/content-packs/groupbuy-promo-v2/。
- catalog.json：50套执行配方、稳定编号、原始路径及SHA-256。
- source/：50个独立TXT原文、4份公共说明TXT，以及原始JSON；均保留原始字节。Git禁用这些原文件的换行转换，避免跨平台部署破坏哈希。
- 没有将原文放入前端public目录，公开接口仍不返回私有提示词。
- 重建：在后端目录运行 python scripts/import_groupbuy_promo_templates.py <原始压缩包路径>。脚本先核对50个编号、分类数量、15镜与源文件内容，再写本地文件；不连接数据库、不调用供应商、不扣积分。
- 每套稳定source_key使用 content:groupbuy-promo-v2:<小写编号>-30s；与旧内容包分开，重复启动不重复导入。
- 两批内容在同一事务中导入；新包写入失败会回滚本轮写入，不留下部分新增记录。

自动检查覆盖50套内容与来源、六类数量、800种选填图片组合、草稿公开隔离、旧版本升级、重复启动、编辑保留、删除保留和失败回滚。真实供应商生成效果不在离线测试范围内。
